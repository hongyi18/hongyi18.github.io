# Website structure

## Main webpages

The main pages of the site include:

- index.md (Homepage and introduction)
  - index/
- research.md (Research interests and publications)
  - research/
- teaching.md (Teaching experience and materials)
  - teaching/
- activities.md (Selected highlights and chronological activity archive)
  - activities/
  - _data/ (Records and interface translations for the activity page)
- blog.md (List of blog posts)
  + _posts/ (Posts in markdown. Name convention for posts: "2023-09-04-my-post.md")
  + blog/ (Attachments for each post)
- personal.md (Personal interests and activities)
  - personal/

Each of the main page has a corresponding folder to store the used files and assets. Corresponding pages in Chinese are saved in the folder /zh/. These files and folders should **always be committed to GitHub**.

## Website deployment

The website is built based on the template Minima v2.5.1. The supporting folders and configuration files are as follows

- _includes/ (Reusable components like headers, footers, and social links)
- _layouts/ (Main HTML layouts that define page structure)
  + default.html (Default layout for all pages except 404)
  + home.html (Layout for homepage)
  + page.html (Layout for pages except the homepage)
  + blog.html (Layout for the blog page that lists all posts)
  + post.html (Layout for posts)
  + home_zh.html
  + page_zh.html
- _sass/ and assets/ (Theme styles, page styles, scripts, and shared assets)
- _plugins (Useful plugins)
- .github/workflows/ (Workflow file for how github page is to be deployed)
- 404.html (For pages that do not exist on the server)
- _config.yml (Main configuration file for site settings)
- Gemfile (Define which gems are required by the application)
- minima.gemspec (Define the metadata and dependencies of a gem)
- Gemfile.lock (Record the exact versions that were installed to avoid inconsistent dependencies)

These files and folders should **always be committed to GitHub**.

## Maintenance files

- README.md (This file. Repository documentation)
- .editorconfig (Define consistent coding styles across different text editors and IDEs)
- .gitignore (Specify patterns of files and directories to be ignored when committing to the repository)
- tests/ (Automated checks for activity data, templates, and other features)
- docs/ (Maintenance instructions)

These files and folders are useful for maintenance, but not required by online website deployment. It is still recommended to commit them to GitHub so that they remain available after cloning onto another computer.

## Local repository data

In local repository, there could be files generated by Jekyll or Git, including

- .git (Local Git repository metadata, including version history, branches, and remote settings. Managed by Git; do not delete or commit manually.)
- _site (Generated website output; recreated by the next build)
- .jekyll-cache (Store pre-generated website files to speed up the build process)

They should **not be committed to GitHub**.
